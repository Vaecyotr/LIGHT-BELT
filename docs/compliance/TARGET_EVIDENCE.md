# 销售前人工取证清单

本清单面向实际发行负责人。仓库审计没有连接控制器、运行 RK3588 命令、读取销售设备镜像或向外发布源代码。目标是把 [OPEN_RISKS.md](OPEN_RISKS.md) 中的未知项变成可核验的交付记录。

## 1. 确定销售版本

记录销售主体、国家/地区、产品型号、软件发行号、系统镜像 SHA-256、硬件/控制器型号与批次。列出每项实际交付内容：磁盘镜像、预装应用、控制器固件、安装/更新包、前端产物、演示媒体、说明书及是否交付源码仓库。将不交付的历史源码、诊断固件和测试素材明确排除。清单应与打包结果逐文件核对。

交付 Python 文件或让客户看见代码，不会单独形成开源许可证授予；客户可用范围取决于有效许可和第三方条款。需要保留专有权利时，先确认权属并制定对应的客户使用/分发许可。

## 2. 从最终 RK3588 镜像采集软件身份

由操作员在待销售镜像上运行只读查询，保存原始输出，并记录采集时刻和镜像发行号。以下命令是给目标 Linux 设备的操作指引，本次未执行：

```sh
cat /etc/os-release
uname -a
dpkg-query -W -f='${binary:Package}\t${Version}\t${source:Package}\t${source:Version}\n'
mpv --version
ffmpeg -version
ffmpeg -buildconf
```

某命令不存在时记录缺失，不安装替代版本来充当原镜像证据。对每个交付包保留 `/usr/share/doc/<包名>/copyright` 与 applicable license/source-package files；保留系统镜像供应商的内核、bootloader、补丁、GPU/无线固件版权和再分发依据。`--enable-gpl`、`--enable-version3`、`--enable-nonfree` 等选项须与实际链接的编解码器库一起判断，不能仅依据可执行文件名判断许可证。

在应用的实际 Python 环境执行 `pip list --format=json`（若该环境提供 pip）或等效的 installed metadata 导出，保存每个实际 wheel 文件/安装来源、版本、哈希、包内 LICENSE/NOTICE/COPYING 和原生 `.so` 依赖。若使用 uv 管理，另保存 uv 的版本和实际同步命令。Windows `.python` 目录中已生成的许可证只是开发机证据。

前端记录发布文件哈希、对应源码/lockfile、构建工具版本以及随包的 `THIRD_PARTY_NOTICES.txt`；独立核验生成产物与输入相符。不要以 lockfile 中“可能存在”的依赖推断产物确实含有该代码。

## 3. 逐控制器确认固件

拍照记录实际 GLEDOPTO 标签、型号、批次与供货来源。保存实机 Info/About 页面或可信固件版本读取、build ID、可取得的固件文件与 SHA-256。核实厂商包的版本/哈希与实机对应关系。

向实际供应商取得其可再分发依据、第三方许可/署名、上游版本、修改清单及匹配的源码/构建配置。若实际为 WLED，按该版本与文件的许可证履行；不能把现代 EUPL、旧 MIT、厂商私有模块或本仓库自研 ESP32 固件混为一个授权结论。核验源码是可用的对应版本，而非通用项目首页。

## 4. 媒体和权属文件

对媒体建立“交付文件 SHA-256 → 原始作品 → 权利人 → 授权文件 → 地区/期限/允许用途”的记录。对视频中的音乐、录音、画面等分别核对必要权利；保留合成素材的生成方法和输入来源。没有证据的素材先移出销售候选清单，再由权利人授权或选择有证据的替代内容；本次审计没有删除或替换现有媒体。

对自研代码，取得实际创作者、雇佣/委托或受让关系的确认及外部贡献授权。Git 署名中的工具名称不是能够签署转让的权利人；应追溯实际组织和人员。补充基线/汇总提交的来源说明时，按真实资料记录，不能事后编造隔离开发流程。

## 5. 交付源码材料并验收

按 [SOURCE_AVAILABILITY.md](../../SOURCE_AVAILABILITY.md) 为实际 GPL/LGPL/EUPL 组件选择合法的提供方式。最初发行可选择随产品提供相应第三方源码与构建材料，降低依赖未验证网页或长期书面承诺的风险。对 LGPL 静态组合验证重新链接路径；对实际适用的 GPLv3 User Product 核对安装信息条件。不要无差别公开 Host、APP 或硬件设计。

验收至少包括：客户收到完整通知、能够取得匹配源码、源码包有版本/补丁/构建说明、重新链接或安装条件得到满足、第三方权利未被专有 EULA 排除、媒体授权覆盖交付场景。负责人基于具体证据关闭 R1–R8，保留签字/日期/发行身份及交付样本。
