# NanoPC-T6 deployment remediation

## Scope and baseline

The baseline is `403922a459619d60c68844de58a9ad287236388b` on branch `1108`.
The supported deployment is NanoPC-T6, Ubuntu 22.04, aarch64, user `pi`, a
GNOME Wayland session and the checkout at `/home/pi/LIGHT-BELT`.
The worktree was clean before implementation.

## Deployment contracts

- Platform and Python preflight precede system changes. The fixed pair is
  uv 0.9.5 and CPython 3.11.14, whose aarch64 GNU build is in the uv release
  metadata. A valid existing Python 3.11 venv remains in place. An invalid
  existing environment is rejected. Download failure precedes venv sync.
- Independent update policy runs before APT package installation. It disables
  periodic updates, APT timers and targeted update/upgrade/Apport notifications.
  `.list` and deb822 sources retain other repositories and suites while
  jammy-proposed is disabled and pinned negative. Manual APT remains usable.
- Policy changes reject active APT transactions and unsafe source formats or
  links. Original configurations receive one preserved backup and writes use
  atomic replacement. Installed proposed packages are retained for operator
  review. The unattended-upgrades shutdown waiter is not a package transaction.
- System installation requests only missing dependencies with `--no-upgrade`.
  It performs no system upgrade or dist-upgrade.
- Host, default audio and Bluetooth priority run as user services. Host linger
  provides boot startup. GNOME autostart imports its real session and restarts
  Host. The user runtime owns mpv IPC. Native Wayland/EGL uses an immediate
  fullscreen window. Desktop/GDM login policy remains unchanged by default.
- Per-device credentials are generated once or migrated from the old root
  EnvironmentFile, remain private to pi and survive repeated deployments.
  User runtime path/backend assignments take precedence at Host execution.
- Public Bluetooth pairing services remain system services. BlueZ updates
  preserve vendor settings and comments and change effective active keys.
  Existing native PulseAudio loopback ownership and stream mute ownership
  remain intact. An active pipewire-pulse stack is rejected for review.
- Kiosk is explicit opt-in. LIGHT-BELT automatic updating is disabled. Failure
  recovery restores previous Host activation and running state so a failed
  system-to-user migration does not enable two Hosts at the next boot.
- Acceptance checks require a ready real Host, native PulseAudio/default audio
  and public controller state. With a graphical session, mpv IPC must confirm
  configured fullscreen Wayland output. The updater captures that readiness
  function before Git transitions and reloads user units through the real bus.

## Device acceptance and limits

The complete runbook and reboot/no-SSH acceptance commands are in
[the deployment guide](../current/rk3588-bootstrap.md).
Physical black-screen visibility, the BSP GPU/codec drivers, actual Bluetooth
pairing/A2DP audio, mDNS, and power-cycle behavior are
**NOT HARDWARE VERIFIED**.

The fullscreen window requires the pi graphical session. Existing GDM login
and idle/locking policy is preserved unless Kiosk is explicitly requested.
Old proposed packages are not automatically downgraded or removed.
Network/download or driver failures remain explicit deployment failures with
logs and original configuration backups available.
